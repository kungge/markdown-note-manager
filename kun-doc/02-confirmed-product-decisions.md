## 1. 平台和产品形态

1. 首版同时支持 macOS 和 Windows。
2. 最终产品形态是一键安装的桌面客户端。
3. 为降低首期复杂度，先采用“本地服务 + Web UI”的本地优先方案。
4. 代码结构必须保留未来使用 Tauri 或 Electron 封装桌面客户端的演进空间。
5. 本地服务默认只监听 `127.0.0.1`，不能因近期有局域网需求就默认暴露笔记。

## 2. 编辑能力

1. 首版内置编辑器只需要支持轻量修改。
2. 长期目标是完整覆盖日常 Markdown 编辑，逐步替代 VS Code。
3. 在替代完成前，应保留“在 VS Code 中打开”能力。
4. 所有新建笔记必须具有 Front Matter。
5. 历史笔记不强制批量补写 Front Matter，避免制造大规模 Git diff。

## 3. Git

1. 前期远端和同步方式固定，只考虑单 remote。
2. 首版只显示 Git 状态，不执行提交、拉取和推送。
3. 后期支持多个分支，不要求支持多个 remote。
4. Git 展示范围只包括 NoteHub，即使 Git 仓库根目录位于 NoteHub 上级目录。

## 4. 图片

1. 当前通过 VS Code PicGo 插件上传图片到阿里云 OSS。
2. 首版只需要正确预览已有的 OSS 图片。
3. 后续图片上传不能依赖 VS Code 插件内部 API，应采用 PicGo CLI、PicGo Server 或独立兼容适配器。

## 5. 跨设备状态

收藏、最近访问和保存查询需要跨电脑同步。建议后续保存在工作区内专用的、可读的配置文件中，并纳入 Git：

```text
.note-manager/
  shared-state.json
```

约束：

- 不保存绝对路径，统一使用工作区相对路径。
- 不保存搜索结果正文，只保存查询条件。
- 写入采用稳定排序，避免产生无意义 Git diff。
- 多设备同时修改时必须能够提示或合并，不能静默覆盖。

## 6. 工作区边界

1. 只管理 NoteHub 目录。
2. 不管理同一 Git 仓库中 NoteHub 之外的历史笔记。
3. Git 状态、搜索结果、文件操作都必须遵守这一边界。

## 7. 局域网和移动端

近期需要手机或平板只读访问，规划为独立阶段：

1. 本机模式继续只监听回环地址。
2. 用户显式开启后才允许局域网访问。
3. 局域网模式必须具备身份认证、会话过期、CSRF 防护和访问日志。
4. 局域网模式仅允许浏览、搜索和预览，不提供编辑、文件管理或 Git 操作。
5. 不在首版中直接实现公网访问。

## 8. 敏感目录

财务、工作和账号类笔记需要额外隐藏。建议分两步实现：

1. 首版支持配置隐藏路径，使其不出现在目录、搜索、最近访问和统计中。
2. 后续增加“受保护区域”，查看前需要本机二次验证或独立口令。

必须明确：界面隐藏不等于加密。需要真正保护磁盘内容时，应依赖操作系统磁盘加密或另行设计端到端加密。

## 9. 删除策略

1. 删除操作优先进入系统废纸篓。
2. 应用不提供默认永久删除。
3. 归档与删除是两个独立动作：归档移动到仓库内归档目录，删除进入系统废纸篓。

## 10. 实施顺序

```text
阶段 0：只读验证版
  ↓
阶段 1：轻量编辑与安全文件管理
  ↓
阶段 2：Git 状态完善、工作流、任务、Front Matter、PicGo
  ↓
阶段 3：桌面安装包与局域网只读访问
  ↓
阶段 4：高级编辑与智能增强
```

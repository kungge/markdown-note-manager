## 1. 阶段目标

在完全不修改 NoteHub 文件的前提下，验证目录浏览、全文搜索、安全预览、外部修改刷新和 Git 状态能否显著改善现有使用体验。

## 2. 本阶段范围

- 指定一个本地工作区。
- 扫描 Markdown 文件并建立内存索引。
- 按路径浏览和选择笔记。
- 搜索标题、路径和正文。
- 渲染 GFM、代码块、任务列表、Mermaid、远程与本地图片。
- 监听外部文件变化并通知 Web UI 刷新。
- 显示分支及限定在工作区内的 Git 文件状态。
- 通过相对路径配置隐藏敏感目录。
- 点目录默认不进入目录、搜索、预览或 Git 状态视图。
- 生产构建由本地服务托管，不需要额外 Web 服务器。

## 3. 明确不包含

- 新建、编辑、移动、重命名或删除笔记。
- Git 暂存、提交、拉取或推送。
- PicGo 上传。
- 收藏、最近访问和保存查询的跨设备写入。
- 局域网开放及身份认证。
- 桌面安装包。

## 4. 安全边界

- 本地服务默认绑定 `127.0.0.1`。
- 所有文件查询都经过工作区边界检查。
- 本地资源接口只返回受支持的图片类型。
- 隐藏路径不能通过文档或图片 API 绕过。
- Git 通过参数数组调用，不执行拼接后的 Shell 命令。
- Markdown HTML 经过白名单清理，禁止脚本执行。

## 5. 已知限制

- 当前索引保存在内存中，重启后重新扫描；SQLite/FTS 放到后续阶段。
- 中文搜索采用大小写归一化后的连续文本匹配，适合当前规模，但尚未实现高级查询语法。
- 敏感目录“隐藏”不是加密或访问控制。
- Git 状态只读展示，不处理冲突。
- Wiki Link 暂未转换为可点击链接。

## 6. 验证方式

```bash
pnpm typecheck
pnpm test
pnpm build
```

真实工作区验证时，需要检查：

1. NoteHub 扫描数量是否符合隐藏和忽略规则。
2. 中文标题、正文和路径搜索是否能命中。
3. OSS 图片、相对图片、Mermaid 和任务列表是否正常展示。
4. VS Code 修改文件后页面是否刷新。
5. Git 状态是否只包含 NoteHub 范围内的文件。
6. 隐藏目录是否不会出现在列表、搜索和资源接口中。
